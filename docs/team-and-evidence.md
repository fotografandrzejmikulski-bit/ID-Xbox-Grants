# Team & Evidence Package

## Required team dossier

The external application should contain only verifiable statements. Maintain one evidence record per material claim.

| Evidence ID | Item | Required proof |
|---|---|---|
| E-01 | Legal entity | Registration / corporate record |
| E-02 | Team size | Current roster |
| E-03 | Key roles | Responsibility matrix |
| E-04 | Commercial credits | Public release pages / platform credits / contracts where available |
| E-05 | Project ownership | IP / chain-of-title documentation |
| E-06 | Current project state | Build, screenshots, gameplay capture |
| E-07 | Technical stack | Repository/build documentation |
| E-08 | Production plan | Approved roadmap + milestones |
| E-09 | Budget | Rate cards / quotes / assumptions |
| E-10 | Accessibility work | Feature matrix + player testing evidence |
| E-11 | Platform readiness | Capability matrix + target-device test logs |
| E-12 | Marketing readiness | Trailer, key art, store assets, press kit |

## Evidence hierarchy

1. Primary Microsoft documentation or agreement.
2. Official studio documentation and current project artifacts.
3. Direct vendor quotations and contractual evidence.
4. Public third-party information.
5. Internal assumptions and forecasts.

Only the first four categories should normally support factual claims in the external application. Forecasts should be explicitly labeled as forecasts.

## Diversity / representation claims

Where the application discusses underrepresented creators, describe the team's real composition and leadership accurately. Avoid collecting or exposing unnecessary sensitive personal data. The strategic case should remain grounded in the project's originality, execution ability and barrier-removal need.
